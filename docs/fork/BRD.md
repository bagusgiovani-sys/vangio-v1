## Business Objectives
**Why this exists:** Existing tools like Claude Code/Cursor require paid subscriptions. Wants a Claude Code-like terminal experience that's free or cheap to run, tailored to your own workflow, and a chance to learn agent-tool architecture.
**Success at launch:** Daily use on real freelance work, without wanting to switch back to OpenCode/Aider/Claude Code.
**Key metrics:** Daily personal use; completes at least one full feature/task end-to-end; understand the forked codebase well enough to modify it confidently.
**Failure condition:** Breaks/crashes constantly, unusable.

## Model Access Strategy (revised after hardware check + provider research)
> UPDATED 2026-07-16: Default switched from GLM-4.7-Flash to DeepSeek V4 Flash Free (via OpenCode Zen), after GLM's 1-concurrent-request limit caused OpenCode to retry forever in real use (documented OpenCode GitHub issue #8618, affects even paid GLM users). DeepSeek V4 Flash Free scores ~79% SWE-bench Verified (vendor-reported) — near Sonnet-tier, well above GLM-4.7-Flash's ~59.2%. **UNVERIFIED: whether Zen's gateway actually resolves the concurrency issue, or whether it's an OpenCode-client-side bug that follows to any provider — needs real-world confirmation with a multi-tool-call session.**
**Default provider:** DeepSeek V4 Flash Free (OpenCode Zen) — free, but a temporary promotional tier, not permanent. Data may be used to improve the model during the free period (not zero-retention) — personal/hobby use only, not safe for freelance client work.
**Fallback provider:** GLM-4.7-Flash (Zhipu/Z.ai) — genuinely free, ongoing, no expiry, but throttled to 1 concurrent request which breaks OpenCode's default retry behavior. Kept configured as a manual-switch option, not default.
**Secondary cloud options:** Qwen (only free via local Ollama now — cloud free API tier ended April 15, 2026) and Kimi (not genuinely free — requires min. $1 top-up before use) — available as configured fallback profiles.
**Tertiary/optional:** Local Ollama (7–8B models) — for offline use, privacy-sensitive snippets, or experimentation; not relied on for daily real work due to hardware limits (16GB RAM, integrated graphics only, CPU-bound inference).
**Explicitly out of scope:** Ollama Cloud (adds cost + no better than GLM's genuine free tier for this use case); actual paid Claude/GPT/Gemini APIs (defeats the "free" goal, though technically supported by OpenCode if ever needed).
**Expectation set:** GLM-4.7-Flash performs at Haiku-tier — reliable for straightforward tasks (bug fixes, small features, boilerplate), weaker on complex multi-file refactors or long agentic sessions.

## Reference & Differentiation
**Similar to:** OpenCode (sst/opencode), Aider, Claude Code, OpenClaude
**Fork base:** OpenCode (sst/opencode, mirrored at anomalyco/opencode) — TypeScript + Bun, MIT licensed, independently built (no leaked-code legal risk). Switched from initial OpenClaude choice after deep comparison: OpenCode has ~160K+ stars vs OpenClaude's ~29K, is backed by a real team (SST/Anomaly), and has clean IP — better fit given eventual commercial plans.
**Windows setup:** Native Windows 11 (Git Bash). WSL2 was the original choice — OpenCode's officially recommended path for full compatibility — but was **ABANDONED (2026-07)** after Error 14098 component-store corruption blocked feature registration and survived DISM RestoreHealth. Native Windows remains a second-tier support path upstream, but it is the verified v1 environment in daily use here.
**Known limitation, accepted:** Free/open models (Qwen, and likely GLM) don't always follow tool-calling protocol as cleanly as Claude does — documented OpenCode GitHub issue shows Qwen3.6 continuing to generate text instead of stopping properly after a tool call. This is a category-wide issue with free models, not specific to one fork choice.
**Known past friction (not directly relevant):** Anthropic blocked OpenCode's access to consumer Claude Pro/Max OAuth in Jan 2026 — irrelevant to VanGio since the plan never relied on a Claude subscription.
**Better than references at:** Not yet decided — deliberately deferred until after v1 ships. **Candidate differentiator logged (post-v1):** built-in free local codebase indexing (RAG — chunker + embedding model + local vector store + retriever + file watcher). This is a genuine engineering feature, larger than all of v1 combined, so it is explicitly NOT in v1. Before building from scratch post-v1, verify whether OpenCode already offers codebase-context/retrieval or a plugin for it (search results referenced wiring OpenCode to a vector DB like Milvus/Zilliz). Note: the embedding step still requires a model (local = slow on current hardware; API = another provider dependency).

**Second candidate differentiator logged (post-v1):** a VanGio *native side-panel* VS Code/Cursor extension — a docked, resizable, layout-persistent panel that feels first-class in the IDE (status indicator, config UI, project-aware context via editor APIs), NOT just a terminal wrapper. Verified gap: OpenCode's current extension only spawns the CLI in the integrated terminal; a native panel is an open, unbuilt feature request upstream (GitHub issue Jan 2026). This is post-v1 and separate from v1's terminal-only scope.
**Deliberately NOT doing:** Training a custom foundation model; team/multi-tenant features; macOS/Linux-native support in v1 (Windows-only, native — no WSL2 dependency); solving commercial differentiation yet
