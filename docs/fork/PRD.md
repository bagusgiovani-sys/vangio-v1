## Overview
VanGio v1 is a fork of OpenCode, running **natively on Windows 11** (WSL2 was abandoned — unfixable Error 14098 component-store corruption), configured to default to **DeepSeek V4 Flash Free** (via OpenCode Zen) with **GLM-4.7-Flash kept as a configured fallback** (throttled to 1 concurrent request) and Qwen/Kimi as additional switchable provider profiles, and local Ollama as an optional tertiary mode. Goal: a daily-usable, free/cheap terminal coding assistant for real freelance frontend work.

## Priority Matrix (MoSCoW)

### Must Have (v1 blocks without these)
- Native Windows OpenCode install (WSL2 abandoned), DeepSeek V4 Flash Free default (via Zen) + GLM/Qwen/Kimi profiles configured (GLM as fallback, not default)
- Provider switching (manual, mid-session) + rate-limit/overload handling with clear error messaging
- Core coding agent loop (inherited from OpenCode): read/edit files, run shell commands, multi-step tool-calling loop, streaming output, LSP integration for TS/JS
- Basic error handling — a failed request must not crash the whole session
- Startup banner — **build order: FIRST**, per 2026-07-16 reorder (was last). Owl face + `cfonts` "VANGIO" wordmark + "by bagusgiovani" byline + ANSI blink cursor; design already verified in a real sandbox run. Supersedes the original plain-text placeholder spec.

### Should Have
- Config folder/CLI output renamed from OpenCode → VanGio (e.g. `.vangio/` instead of `.opencode/`)

### Could Have (post-v1)
- Custom pixel-art mascot logo (parked — revisit later using a proper pixel-art tool, not hand-typed ASCII)
- Local Ollama tool-calling reliability workaround (known category issue with free/open models)
- Smarter quota-aware provider suggestions (e.g. auto-detect GLM throttling and proactively suggest Qwen)

### Won't Have (explicitly out of scope for v1)
- Team/multi-user features
- macOS/Linux-native support (v1 is Windows-only, native — no WSL2 dependency)
- Commercial/monetization features
- Training a custom foundation model
- Ollama Cloud integration (rejected — not truly free, reliability concerns)

## Command/Setup Inventory (CLI equivalent of screen inventory)

1. **Install & Setup Flow** — Native Windows OpenCode install (`npm i -g opencode-ai@latest`, no WSL2) → first-run provider wizard (configures DeepSeek V4 Flash Free default via Zen, plus GLM/Qwen/Kimi profiles) → config saved to `~/.vangio/config`
2. **Startup Banner** — owl face + `cfonts` "VANGIO" wordmark + "by bagusgiovani" byline + ANSI blink cursor, shown on every launch (built first, per 2026-07-16 reorder)
3. **Main Interactive Session** — prompt input → streaming response → live tool-call execution (file edits, shell commands) → active provider/model shown in session
4. **Provider Switch Command** — manual mid-session command to swap between DeepSeek (default) / GLM (fallback) / Qwen / Kimi / local Ollama
5. **Error/Rate-Limit State** — clear message on 429/overload, suggests switching provider, does not crash session
6. **Exit/Session End**

## User Stories

- As a freelance frontend engineer, I want the CLI to default to a free model so I don't incur costs during daily coding work.
- As a solo developer on a hardware-limited laptop (16GB RAM, no dedicated GPU), I want cloud-based free models as the default so my hardware doesn't bottleneck responsiveness.
- As a user who may hit free-tier rate limits, I want clear error messages and an easy way to switch providers so I can keep working without the session crashing.
- As a first-time user, I want a guided setup wizard so I don't have to manually configure WSL2/OpenCode/providers by hand.
- As the builder, I want the tool to feel like my own (VanGio branding, even minimal) rather than an unmodified copy of OpenCode.
